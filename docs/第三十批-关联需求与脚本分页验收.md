# 第三十批：测试用例关联需求与脚本分页、错误恢复验收

日期：2026-11-12。本地仓库：`D:\code\dev-process-manager`。

## 原问题与结论

经检查 `TestCaseService.availableRequirements()` + `TestCaseMapper.selectAvailableRequirements` 和 `TestCaseService.scripts()` + `TestCaseMapper.selectEnabledScripts`，两个旧接口均**返回全部记录**，并没有“只返回前100条”的截断。但是数据量增大后，需求一次性返回、脚本选项包含多余的修订详情字段，存在不必要的响应体和页面渲染负担。更重要的是：旧 `TestCaseListView.loadRequirements` 请求失败仅弹一次提示、未清除上次选择；编辑时在选项未完整加载的情况下可能保存旧或缺失的关联数据。

## 后端变更

- 新增 `GET /api/test-cases/available-requirements/page?versionId=&pageNum=1&pageSize=100`，返回 `PageResult<TestCaseRequirementDTO>`（list、total、pageNum、pageSize）。
- `TestCaseMapper.xml` 加入 `countAvailableRequirements` 和 `selectAvailableRequirementsPage`，支持按版本过滤，排序在项目/版本/顺序/编号之外加 `r.id` 稳定分页。只查询关联选项必要的编号、标题、项目与版本信息，**不返回正文 Markdown、历史快照或脚本源码**。
- 页码与每页条数限制合法范围、每页上限100、避免偏移溢出，异常参数返回400；Service 标记只读事务。
- **旧 `GET /api/test-cases/available-requirements` 与 `GET /api/test-cases/scripts` 仍保留**，维持旧调用兼容。脚本选择直接复用已经存在的 `GET /api/test-scripts?enabled=true&pageNum=&pageSize=` 分页接口（返回不含源码的摘要）。
- 不新增表或 DDL，不改变用例的保存规则及旧关联关系。

## 前端变更

- `TestCaseListView.vue` 的需求、脚本选择都复用 `loadPagedOptions`，每页100条、最多5000条，检查重复ID、页数和总数漂移，不再无界请求全部关联。
- 用例的需求选项分页结果仍保留 `requirementId` 给原 UI 的多选框使用，附加 `id` 用于通用完整性校验；版本筛选保持生效。
- 两类选择增加持续可见的错误、加载状态和重试；新旧请求有独立序列号，快速切换版本时迟到的请求不会覆盖新选择。
- **保存安全**：需求选项加载中或失败时，禁止保存；脚本方式下脚本列表加载中或失败时，也禁止保存。防止编辑用例时在残缺选项状态下误覆盖需求关联或脚本配置。
- 脚本空列表提示改为“暂无已启用脚本，请到脚本管理启用”，去掉已过期的“脚本管理下一阶段补齐”提示。
