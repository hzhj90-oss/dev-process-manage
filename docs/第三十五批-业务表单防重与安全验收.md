- 基线：第三十四批全部回归通过，保留已有未提交改动和业务数据库。
- 本批目标：修复高频业务编辑表单在异步校验完成前尚未锁定保存导致的双击重复创建/修订风险，保障关联目标固定与失败可恢复。

## 发现与实现

1. 需求管理（RequirementListView）：新增编辑会话令牌，保存前同步设置锁；编辑中禁止关闭/切换，更新使用打开编辑时固定的目标 ID。版本下拉选项通过 latest-only 加载，失败可重试；加载不完整时禁止保存，避免错误版本关联。
2. 详细设计：新修订保存时，在异步 Element Plus 表单校验之前同步设置 designSaving，防止双击导致两条不可变修订；父需求 ID 和会话令牌继续固定，关闭期间禁止切换父对象。
3. 测试用例（TestCaseListView）：把表单校验、步骤完整性检查及请求提交纳入同一个保存临界区；校验失败释放锁，防止多次创建新修订；请求结束无条件清理保存状态。
4. 自动化脚本（TestScriptListView）：把脚本必填项与参数 JSON 校验也纳入保存锁，禁止双击重复创建、重复修订；失败允许重试。
5. 测试轮次（TestCycleListView）：轮次字段、测试范围 JSON 与最终保存请求共用锁，避免生成重复轮次和用例快照。
6. 所有修改保留既有的后端 API、数据库表与 Runner 功能，不增加 Docker、Python/Java 执行器、登录/权限校验，也不触碰历史异常轮次。
