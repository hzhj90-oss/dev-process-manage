# 第四十二批：需求到关联用例创建与日常上手指引

日期：2026-11-12；T14s 根目录：D:\code\dev-process-manager

## 起因与用户实际阻塞

第40批新增“需求 → 关联用例列表”精确下钻；但需求列表里的关联计数为0时按钮是禁用的，也缺少“直接为这条需求创建测试用例”入口。用户进入用例页后点击新建，用例并不会预选原需求；在同一个版本含多个需求，或者多版本并行时，容易漏掉需求覆盖关系。

本批针对真实业务流程，补齐“需求 → 新建关联用例 → 选中来源 → 填写步骤 → 创建 → 返回该需求用例列表”闭环，不引入新表和模块。

## 已开发功能

### 需求列表（RequirementListView.vue）

- 关联用例计数即使为 **0 条**也允许点击进入带 requirementId 的精确筛选列表，空列表有可操作入口。
- 需求行操作区新增“**新增用例**”，只用严格校验的来源需求 ID 构造 test-cases?requirementId=ID&create=1 深链，不携带可伪造的需求标题/版本元数据。
- 原“编辑”“设计”入口不变。

### 测试用例（TestCaseListView.vue）

- 用户从需求深链到达、或在需求筛选用例列表点击“**为此需求新增用例**”，打开新建用例编辑框，立即读取后端真实需求详情（GET /api/requirements/{id}），校验 id、versionId、编号和标题；**仅客户端 URL 不够作为保存依据**。
- 自动把选择“筛选版本”设为真实需求所属版本，再完整分页加载该版本可选关联需求；将来源 requirementId 加入 form.requirementIds，同时展示来源编号和标题。
- 当来源已选定后锁定版本筛选，防止用户误切版本导致来源需求消失。允许在同版本中继续添加其他需求关联；如要创建独立/跨版本关联用例，回“全部用例”使用普通新建入口。
- 点击“创建用例”前再次核验来源 id 仍等于当前路由需求 id，版本一致、可选关联清单中确实存在来源需求、且用户未移除该关联；不满足时禁止 POST 并显示可理解的错误。
- 来源详情读取异常、响应不匹配、候选加载失败或来源不在候选中：表单保持打开但禁止提交；提供“重试读取关联需求”。请求旧响应只有当前 editorGate token 能写入 UI，避免 A/B 需求快速切换时串数据。
- 保存成功后关闭编辑框，去掉 create=1 URL 标记，但保留 requirementId 精确筛选上下文；创建结果应显示在来源需求的用例列表。
- 创建表单未主动生成用例编号或内容，也没有自动执行测试，更没有暗中写数据库；执行模式默认为 MANUAL。

### 首页快速入门（DashboardView.vue）

- 首页实时统计和原8个模块入口不变；新增“第一次使用？按这6步完成一个版本”模块，分别链接项目、版本、需求/设计、用例、测试轮次、报告。
- 每步明确用途，并提醒需要先有测试环境，脚本方式须启用脚本、创建轮次不等于自动执行。
- 桌面3列、平板2列、移动设备1列的响应式布局，不添加依赖、不请求新API。
- 修改原 dashboard Chrome 验收同时核对6个链接与提示，不影响原6项真实统计核对。

### 使用文档

- 新增 docs/使用指南-从版本到测试报告.md，说明：核心概念、项目/版本/需求/设计/用例/环境/轮次/任务/报告的完整使用步骤；新关联用例入口；ChatGPT交接与固定脚本区别；轮次对比口径；常见错误；进程守护、备份与恢复边界。
