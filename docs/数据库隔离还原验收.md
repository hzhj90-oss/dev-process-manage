## 使用与保护

**默认只读预检**（校验备份 SHA-256、GZip / ZIP 内容完整性、SQL 结构和跨库命令，不启动数据库）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-database-isolated-restore.ps1
```

**显式独立还原测试**：

```powershell
$env:DPM_ISOLATED_RESTORE_ALLOW_WRITE = 'YES'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-database-isolated-restore.ps1 -Apply
Remove-Item Env:\DPM_ISOLATED_RESTORE_ALLOW_WRITE
```

**统一回归并包含真实隔离还原**（默认不执行还原）：

```powershell
$env:DPM_ISOLATED_RESTORE_ALLOW_WRITE = 'YES'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-local.ps1 -AuditDependencies -IncludeMySql -BrowserIntegration -IsolatedRestoreE2E
Remove-Item Env:\DPM_ISOLATED_RESTORE_ALLOW_WRITE
```

缺少环境变量时，`-IsolatedRestoreE2E` 在启动统一回归前立即拒绝，退出码 1。未启用 `-Apply` 的独立脚本只预检，退出码 0。

## 安全边界和实现细节

- 原运行实例为 `127.0.0.1:3306/dev_process_manager`。还原脚本**不读取此数据库密码，不连接、不写入原业务实例**。
- 还原前先调用 `verify-database-backup.ps1`，再检查 SQL 语句中是否有 `USE`、`CREATE/DROP DATABASE`、用户和全局权限变更、文件导入导出等不允许的指令。
- 备份来自自动备份目录下的标准命名文件夹，不能任意指定外部 SQL 路径。
- 临时 MySQL 使用本机 MySQL 5.7.44 二进制、唯一数据目录、系统分配的临时回环 TCP 端口，`--no-defaults` 避免读取业务服务配置；关闭 syslog/EventLog，禁用本地文件导入及文件访问导出。
- 仅在本地短暂测试进程内使用无密码初始 root，**不应把这种启动方式用于常驻数据库或面向局域网/互联网的服务**。
- 全流程不安装新 Windows 服务、不调整业务端口、不安装 Docker、不更改 Windows 注册表。
- 该测试证明备份可以还原成可查询的完整库及附件；不是跨机器容灾、密码加密、全部接口业务回归或数据库升级兼容性测试。

## 诊断与已修复的问题

- 初次隔离服务因 Windows 事件日志注册表要求启动失败；使用 MySQL 5.7 `--log-syslog=0`，不用管理员权限修改注册表。
- 初始 root 仅允许 `localhost`，在 `skip-name-resolve` 下拒绝 `127.0.0.1`；已移除该冲突选项。
- PowerShell 变量名不区分大小写：局部 `$backupRoot` 曾覆盖帮助脚本的 `$script:BackupRoot`，导致首份报告输出在自动备份目录下的误路径。已更名为 `$completedBackupDirectory`，误路径的 JSON 报告已迁移并清理。后续报告均保存到正确位置。
- 成功结束后检查 `data\restore-validation` 下没有残留的 `run-*` 目录。
