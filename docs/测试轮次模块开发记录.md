# 测试轮次模块开发记录

## 1. 模块范围

按软件版本组织多轮测试。每个测试轮次必须绑定一个测试环境和一份实际代码基线，并固定本轮测试用例、用例修订、需求覆盖及详细设计快照。

已完成轮次配置、用例清单维护、轮次开始/终止、详情展示，以及与执行任务模块联动的自动完成和结果统计。Runner/ChatGPT 执行编排由执行任务模块负责；截图/文件证据归档和测试报告仍待实施。

## 2. 数据库设计

V1.0.0 已创建 dpm_test_cycle、dpm_cycle_case；V1.2.0 增加环境与需求快照。

| 表/字段 | 用途 |
|---|---|
| dpm_test_cycle | 版本下的测试轮次 |
| dpm_test_cycle.environment_snapshot | 创建/修改轮次时固定的环境配置 JSON |
| dpm_cycle_case | 本轮选择的用例、用例修订及用例内容快照 |
| dpm_cycle_case_requirement | 本轮用例对应的需求正文、覆盖类型和详细设计快照 |

environment_snapshot 包含环境 ID、编码、名称、类型、baseUrl、apiBaseUrl、authType、credentialRef 和非敏感 configJson。
case_snapshot 固定用例编号、名称、修订号、前置条件、步骤、预期结果、执行方式、脚本修订引用、AI 指令和测试数据。
requirement_snapshot 固定需求正文和元信息；design_snapshot 固定创建轮次时最新的详细设计修订，无设计时为空。

## 3. 后端接口

统一前缀：/api/test-cycles

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/test-cycles | 分页查询，支持版本、环境、状态、关键字筛选 |
| GET | /api/test-cycles/{id} | 轮次详情，包含用例及快照 |
| POST | /api/test-cycles | 创建轮次并固定环境、用例、需求和设计快照 |
| PUT | /api/test-cycles/{id} | 修改计划中的轮次配置 |
| POST | /api/test-cycles/{id}/cases | 向计划中的轮次增加用例 |
| DELETE | /api/test-cycles/{id}/cases/{cycleCaseId} | 从计划中的轮次移除用例 |
| POST | /api/test-cycles/{id}/start | 开始测试 |
| POST | /api/test-cycles/{id}/abort | 终止轮次 |

## 4. 业务规则

1. 一个轮次必须属于一个存在的版本，并选择一个启用状态的环境。
2. 同一版本内 cycle_no 自动递增且唯一。
3. cycle_stage 允许 LOCAL_DEV、INTEGRATION_TEST、REGRESSION、PRE_RELEASE、PRODUCTION。
4. code_version 必填；git_branch、git_commit、build_no、scope_json、description 可选。
5. 创建轮次时必须至少选择一条 ACTIVE 测试用例；同一轮次不允许重复加入同一用例。
6. 加入用例时固定其当前修订；关联需求限定为该轮次所属版本下的需求，并固定当时最新设计修订。
7. 只有 PLANNED 轮次允许编辑配置、增加用例和移除用例。
8. 开始测试前必须至少有一条用例；开始后状态为 RUNNING，配置和用例清单锁定。
9. PLANNED 或 RUNNING 状态可以终止，终止后为 ABORTED。
10. 移除轮次用例时，需求快照删除和用例删除均以 cycle_id + cycle_case_id 限定，不能影响其他轮次。
11. 新增用例的 sequence_no 取当前最大 sequence_no + 1，不能用当前记录数代替；因为计划中用例允许删除，记录数可能回落并造成序号重复。

## 5. 状态

- PLANNED：计划中，可编辑轮次配置及用例清单。
- RUNNING：进行中，轮次配置及用例清单锁定。
- COMPLETED：已完成；RUNNING 轮次中的全部用例进入终态（COMPLETED/CANCELLED）后，执行服务自动更新轮次状态和 completed_at。ABORTED 与空轮次不会被自动完成。
- ABORTED：已终止，不再允许执行操作。

## 6. 前端页面

路由：/#/test-cycles

页面能力：
- 按版本、环境、状态、关键字筛选并分页。
- 新建轮次，选择版本、阶段、环境、代码版本、Git 信息、构建编号、范围和初始用例。
- 编辑计划中的轮次配置。
- 查看轮次详情，包括环境快照、代码基线、用例修订、步骤、预期结果、AI 指令、需求正文和详细设计快照。
- 对计划中的轮次增加/移除用例。
- 开始或终止轮次前二次确认。

## 8. Review 修正

- 轮次列表优先读取 environment_snapshot 中的环境编码/名称；快照为空的历史记录回退当前环境表。
- 移除用例的需求快照删除增加 cycle_id 归属检查。
- 增加用例时 sequence_no 改为 MAX(sequence_no)+1，避免先删除中间用例后新增导致排序号重复。

## 10. 自动完成与统计验证（2026-11-10）

- 最后一个用例完成后，执行服务自动将 RUNNING 轮次更新为 COMPLETED，并写入 completed_at；完成状态不依赖单独的前端请求或定时轮询。
- PENDING、RUNNING、WAITING_HUMAN、RECOVERY_REQUIRED 任一状态存在时，轮次保持 RUNNING；ABORTED 和无用例轮次不会被自动完成。
- 列表/详情实时统计 PASS、FAIL、BLOCKED、SKIPPED、NOT_RUN；取消且没有执行结果的用例保留 NOT_RUN。
- 完成人工/ChatGPT 登记、Runner complete/fail、用户取消、人工介入拒绝均接入统一轮次汇总；轮次锁先于父任务、子任务锁定，确保并发最后用例完成安全。
- 无新增 DDL；MySQL 5.7.44 集成测试验证未完成用例阻止结束、ABORTED/空轮次保护、重复汇总幂等，以及两个事务并发完成最后两个用例时轮次只完成一次。
