# 数据库自动备份与恢复验证

日期：2026-11-11。实施主机：T14s / `DESKTOP-07M7V1F`。项目：`D:\code\dev-process-manager`。

## 目标与实现

已实现本地 MySQL 5.7 数据库和上传附件的自动备份，不修改已有数据库表结构和业务代码。

- 数据库：读取被 Git 忽略的 `.local/application-local.yml`，严格检查只能连接 `127.0.0.1:3306/dev_process_manager`；使用本机 `D:\soft\mysql-5.7.44-winx64\bin\mysqldump.exe`，`--single-transaction --quick --routines --triggers --events --hex-blob --no-tablespaces`，先保存 SQL，再压缩成 GZip。
- 附件：归档 `data/uploads` 到 ZIP；拒绝符号链接与重解析路径，避免归档越界。
- 备份位置：`data/backup/automatic/backup-YYYYMMDD_HHMMSS_mmm/`，包括 `database.sql.gz`、`uploads.zip`、`manifest.json`。
- 清单记录备份时间、18 张表/附件数量、文件字节数及 SHA-256。绝不将数据库密码写入命令行参数、Git、备份清单或日志；MySQL 的凭据仅在调用原生命令的子进程环境中短暂传递。
- 原子发布：先输出到 `.staging-GUID` 临时目录，校验 SQL 可完整解压且末尾存在完成标记、表数量一致、ZIP 全量可读、哈希正确后，才移动成正式备份目录；失败时删除临时目录，不影响已有备份。
- 安全：自动备份根目录关闭 NTFS 权限继承，仅为当前 Windows 用户、SYSTEM 和 Administrators 保留完全控制权限。目录在 Git 忽略的 `data/` 中，不会推送到 GitHub。
- 保留策略：默认保留 30 天，且至少保留最近 7 份。仅清理该子目录下符合自动备份命名规则的旧目录，不操作历史手工备份。
- 并发保护：本地 Windows mutex 防止两个备份实例同时写入。
## Windows 每日自动备份

已在 Windows 任务计划程序安装 `DPM-DevProcessManager-DatabaseBackup`。

- 触发器：每天 **02:30（T14s 本机 Windows 时间）**，以及当前用户登录后补查。
- 当前用户 Interactive 令牌、最小权限、不保存 Windows 密码、不唤醒电脑。仅在该用户已登录的情况下执行；关闭或长时间睡眠期间不能保证准时备份。
- 任务调用 `scripts/run-scheduled-backup.ps1`，本地最近 20 小时已有**校验通过**的备份时自动跳过，防止频繁登录造成重复文件。
- 状态日志：`logs/database-backup-schedule.log`；Windows 计划任务的 `LastTaskResult=0` 为成功。
- 安装与卸载只针对该计划任务；卸载不会删除既有备份，且不停止 Java/MySQL/Runner。

## 常用命令

在 T14s 的 PowerShell 中：

```powershell
cd D:\code\dev-process-manager

# 手动创建全新备份（不限20小时间隔）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup-database.ps1

# 验证最新备份：SHA-256、SQL完整解压、表定义、ZIP全部附件
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-database-backup.ps1

# 查看最近备份时间、有效性和计划任务状态；超过48小时未备份会报STALE
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup-status.ps1 -Verify

# 计划任务安装/卸载
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-database-backup.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-database-backup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall-database-backup.ps1
```

再次安装已有任务默认拒绝覆盖，需人工检查后显式使用 `-Force`。

- NTFS ACL 经检查为 protected，仅当前用户、SYSTEM、Administrators 三个主体拥有权限。
- Windows 计划任务已成功实际触发，返回结果为 `0`；卸载再安装测试通过，备份文件和四个应用进程均不受影响。
- 本机当前 MySQL 应用用户**没有创建独立测试数据库的全局权限**，所以**尚未执行完整 SQL 导入/数据恢复演练**。这不是 SQL 还原成功的证明。

## 限制与下一步

- 备份和正在运行的 MySQL 位于同一台机器。如果硬盘故障、电脑丢失或勒索软件破坏整个磁盘，本地备份可能同时损失。正式使用前应增加**加密的异机或离线副本**，并定期在隔离数据库中实际还原演练。
- MySQL 的单事务快照与文件附件的 ZIP 不是跨系统原子事务：备份期间新增或变化的上传文件可能造成极短时间的关联不一致，需要后续业务层快照设计或维护窗口配合。
- 此轮没有提供能直接覆盖生产数据库的自动还原脚本；还原前必须校验清单、隔离导入、核对数据，并明确人工审批，避免误覆盖实时数据库。
- 尚未开发系统级登录鉴权；当前后端只监听 `127.0.0.1:18090`。如计划开放局域网/公网，应先完成登录鉴权与访问控制。

**Git 规则**：本轮与前几轮开发均保持本地未提交状态。仅在用户明确要求提交/推送时才操作 Git。
