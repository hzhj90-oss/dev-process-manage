本批从 docs/开发断点.md 第三十五批继续，以实际页面操作为中心，聚焦慢网、失败重试、双击和目标关联安全，不新增业务模块。

## 代码修改

### 测试轮次：TestCycleListView.vue

- 为增删用例增加单轮次事务前端锁 cycleMutation：点击移除时在打开确认框前锁定，确认取消不发送 DELETE；添加用例提交前校验有效 ID、重复 ID 和可选清单，复制固定的 cycleId/caseIds。
- 加载/保存期间禁止关闭详情和添加弹窗、禁止重复编辑目标与修改选项，防止同一用例产生多张确认框、重复 POST/DELETE、以及异步完成后更新到其它轮次。
- 添加/移除返回必须是同一个轮次 id 且包含 cases；成功后重新 GET 最新轮次详情再刷新列表，不盲目把 POST/DELETE 响应直接放入详情。
- 若请求失败或超时，认为服务端可能已经提交：重新读取服务端最新状态再允许重试；添加弹窗保留，已加入用例会退出可选列表，避免不确定状态下重复修改。

### 自动化脚本库：TestScriptListView.vue

- 启停使用服务端驱动的 el-switch；切换开始同步设置 switchingId，全局暂时禁止其他开关重复事件。
- 收到成功/失败后均重新读取服务器列表，再释放开关锁；不会在服务端拒绝时乐观呈现错误状态。
- 编辑保存的原有保存锁不受影响。

### 执行任务：ExecutionTaskListView.vue

- 取消任务在打开确认输入框前即设置 cancelBusyId；列表、子任务、详情页对应按钮统一禁用，阻止重复弹窗与二次取消。
- 用户确认后 GET 任务最新状态，核对 taskId 和可取消状态；Runner 已提前完成时给出状态变化提示、不再调用取消 POST。
- 网络异常或超时后刷新任务详情、列表和待办数量，确认服务端真实状态，而不是假定请求没有生效。
- 固定取消目标 ID，不依赖刷新后的列表行与弹窗当前对象。

## Chrome 安全验收

新增 runner/browser-runner/browser-mutation-safety-smoke.mjs，挂接 scripts/test-browser-integration.ps1。

- 使用真实无头 Chrome 点击业务页面，而不是直接调用方法。
- 模拟添加用例第一次 503、保留选择并再试；第二次提交在慢网等待时双击仅发送一次。
- 模拟移除用例先取消确认、不产生 DELETE，再双击移除仅一次 DELETE，等待时禁止关闭详情。
- 模拟脚本开关第一次 503、不显示错误的乐观状态；再次双击仅一次 PUT，成功后正确同步。
- 模拟任务取消双击仅一次 POST；已完成任务 GET 状态核验后阻止过期取消。
