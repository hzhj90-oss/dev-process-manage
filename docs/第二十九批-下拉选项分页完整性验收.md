# 第二十九批：下拉选项分页完整性与错误重试验收

日期：2026-11-12。项目目录：`D:\code\dev-process-manager`。

## 缺陷定位

真实代码中发现以下 100 条的隐式截断：

- `VersionListView.loadProjects()` 只请求 `/api/projects` 第一页，项目超过 100 个后无法从“所属项目”中找到后续项目。
- `RequirementListView.loadVersions()`、`TestCaseListView` 挂载函数都只读取 `/api/versions` 第一页，导致后续版本不能用于需求管理和用例覆盖筛选。
- `TestCycleListView.loadOptions()` 对版本只读第一页；对 ACTIVE 测试用例虽循环请求后续页，但遇到空页直接 `break`，未校验重复 ID、总数变化或不完整数据，可能对“全部可选择的用例”形成错误假象。

## 代码变更

新增 `frontend/src/utils/pagedOptions.js`：

- 从第 1 页起按 `pageNum/pageSize=100` 请求直至取齐接口 `total`，保留筛选条件；
- 校验响应中的数组、整数总数、唯一正整数 ID、请求间总数一致、每页容量、缺页/短页；
- 单列表最大 5,000 行（请求页数受限），避免无限循环或无界内存；若超过上限**报错**，不悄悄截断。
- 只有全部页成功完成后才将完整结果交给页面，异常时不返回部分数据。

接入四个核心页面：
`VersionListView.vue`、
`RequirementListView.vue`、
`TestCaseListView.vue`、
`TestCycleListView.vue`。

- 项目/版本筛选以及表单沿用同一份完整选项；
- 异常时显示持续可见的“下拉选项加载失败”告警和“重试加载”操作；
- 轮次页版本、环境、ACTIVE 用例采取同时读取后一次性发布；任一接口失败，三种选项均清空并显示错误，避免使用残缺数据创建轮次；加载中或失败时禁用“新建测试轮次”，增加用例入口也拒绝不完整状态。
- 没有修改原始业务表、后端分页接口、Runner、任务和备份。
