# 第四十五批：本地发布快照、回滚保护与发布前检查

日期：2026-11-12。实施主机：T14s。项目根目录：`D:\code\dev-process-manager`。

## 1. 真实问题与边界

既有 `scripts/build.ps1` 在端口18090占用时拒绝构建。日常更新通常先 `stop.ps1`，再 `start.ps1`（重新构建Vite并运行Maven clean verify），若依赖、编译、启动出现问题，原 `backend/target/dev-process-manager.jar` 可能被清理，而原脚本没有可验证的旧版本恢复入口。

第45批提供**本地 JAR 级回滚准备和受控恢复脚本**，而非数据库迁移回滚。它不能恢复 MySQL、附件或用户数据，不支持未授权联网部署，也不允许未知脚本执行。仍保持前端与后端单入口18090，HTTP/Node/Browser Runner进程独立，无登录权限，不对公网开放。

## 2. 新增文件

- `scripts/release-common.ps1`：JAR可执行结构校验、SHA-256、官方快照ID与目录严格校验、只读进行中任务数量，及同目录校验后换包/恢复原文件辅助函数。
- `scripts/create-release-snapshot.ps1`：复制当前运行且健康的JAR到 `data/release-snapshots/release-YYYYMMDD_HHMMSS_mmm/`，保存 `application.jar` 与 `manifest.json`；先制作到私有临时目录并复核源与副本哈希，成功后原子发布目录。默认实际备份，仅 `-DryRun` 不创建文件。
- `scripts/rollback-release.ps1`：默认**只读预览**；只有明确指定快照ID、64位SHA、`-Apply` 且环境变量 `DPM_RELEASE_ROLLBACK_APPROVE=YES` 才会尝试操作服务；拒绝当前有运行中测试任务的在线回滚；恢复前检验目标JAR，暂停watchdog，受控停止后换包、以`start.ps1 -SkipBuild`启动；若换包/启动失败则尝试恢复原JAR并重新启动，不自动操作真实任务。若原JAR本身仍存在，则必须先有一份通过校验的原版本正式快照。
- `scripts/rollback-release.ps1 -AllowOffline`：额外模式，只有应用进程**完全停止**、18090端口无人监听且显式授权时才能恢复因编译失败造成的丢失JAR；二次检查进程/端口。如果原JAR已丢失且新JAR启动失败，没有可用原文件时会保持watchdog暂停、要求人工介入，绝不悄悄重试业务任务。
- `scripts/check-release-readiness.ps1`：只读检查健康、运行中任务0、Spring Boot与三个Runner单实例、服务端仅监听127.0.0.1或::1、Watchdog/Backup由wscript无窗口执行、最新备份完整性、官方可恢复JAR快照、磁盘至少512MiB、Git diff --check。显示累计未提交数量，使用`-Strict`时额外要求工作区干净，但**不会擅自提交**。
- `scripts/test-release-safety.ps1`：在忽略目录`.local/release-test-<GUID>`内用临时文件测试快照元数据、路径穿越拒绝、篡改后哈希拒绝、没有授权拒绝、SHA不匹配拒绝、在线服务误用离线选项拒绝、同目录JAR替换以及恢复/失败备份逻辑。严禁执行真实`-Apply`；结束后删除临时测试目录。

## 4. 推荐操作流程（命令均建议在隐藏窗口方式执行）

在项目根目录运行：

```powershell
# 日常发布前检查（只读，结果为PASS才继续）
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\check-release-readiness.ps1

# 先确认旧版本的快照策略（只读）
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\create-release-snapshot.ps1 -DryRun

# 真正创建可验证旧版本JAR快照（不停止服务；产生一个私有副本）
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\create-release-snapshot.ps1

# 只读浏览最新的回滚目标
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\rollback-release.ps1

# 独立验证回滚安全保护（只改 .local 内部临时文件；不停止服务）
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\test-release-safety.ps1
```

当且仅当用户明确决定进行JAR回滚，记录目标快照的完整SHA，确认执行任务数0、数据库结构与旧JAR兼容，才可在受控维护时间使用：

```powershell
$env:DPM_RELEASE_ROLLBACK_APPROVE='YES'
powershell.exe -NoProfile -NonInteractive -WindowStyle Hidden -ExecutionPolicy Bypass -File .\scripts\rollback-release.ps1 -Apply -SnapshotName 'release-20261112_113442_631' -ExpectedSha256 'ebd22a3c36f225bc2f50d8f000b058bea369d96807f862330ee3cd043866249b'
Remove-Item Env:DPM_RELEASE_ROLLBACK_APPROVE
```

**注意：当前运行JAR就与上述快照一致，脚本会拒绝这种没有意义的回滚。** 本文只是展示参数示例，不代表本轮调用了Apply。当应用已经完全停止、无法连接API、JAR可能被clean删除时，必须额外显式加`-AllowOffline`，且先人工确认没有Java进程、端口无人监听；不能简单把在线错误强制改为离线模式。

## 5. 数据与安全边界

1. JAR快照与DB备份是不同文件：快照保存源码构建产物，数据库仍由`scripts/backup-status.ps1 -Verify`保证18表及附件完整。发布前必须检查两种都有效。**旧程序可能与新数据库DDL不兼容，JAR级回滚不能逆向数据库迁移。**
2. 快照位于Git忽略的`data/`目录，关闭NTFS继承，当前用户/SYSTEM/Administrators可访问。不要提交到GitHub或发给无关人员；并非异机备份，加密离线/异机容灾仍需单独规划。
3. 快照只证明文件未在归档后被篡改（manifest+SHA），不代表第三方签名可信或任意JAR安全。仅用于已知本地可信构建。
4. 回滚仅切换Spring Boot JAR。Runner不重启；watchdog在受控窗口暂停，恢复失败时保持暂停等待人工处理。不要通过回滚自动重新执行业务测试。
5. 已在Windows PowerShell 5.1验证，不依赖Get-FileHash；安全测试只修改临时文件，不触碰真实任务/数据库。
