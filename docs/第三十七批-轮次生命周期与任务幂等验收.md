# 第三十七批：轮次生命周期与执行任务创建幂等安全

时间：2026-11-12（T14s，本地）；代码目录 D:\code\dev-process-manager。

## 背景与目标

第36批已处理轮次增删用例、脚本启停及任务取消。本批按真实用户操作链继续，针对四项可能影响执行任务的操作：
1. 计划中轮次「开始测试」；
2. 计划中/进行中轮次「终止轮次」；
3. 进行中轮次「创建整轮执行任务」；
4. 进行中轮次「单独执行用例」。

风险是连续双击触发多个确认框、多次 POST，或确认弹窗期间状态被其他浏览器/Runner 修改；请求实际成功但客户端未收到 201/200 时，误用新幂等键产生第二个执行任务。

## 前端实现

TestCycleListView.vue：
- 所有上述入口复用 cycleMutation 同步锁；在确认框或首个 GET 前立即设置。列表开始/终止、轮次详情开始/终止、整轮执行、单用例执行、此前的用例增删，互相排斥。
- 业务按钮在锁定期间 disabled/对应 loading；详情弹窗不允许中途关闭。防止不同入口重复、交叉操作。
- 「开始」和「终止」保留二次确认。确认后强制 GET 最新轮次 ID、状态与 cases 数组；状态已过期或无用例时，明确拦截，不向服务器 POST。接口返回必须核对轮次 ID 和目标状态。
- 「创建整轮」二次确认后再次核对 RUNNING 和非空用例；「创建单例」在 POST 前再次核对轮次 RUNNING 和目标 cycleCaseId 仍属于本轮。成功的创建响应必须核对 task ID、taskType、cycleId、cycleCaseId。
- 所有写操作异常均由轮次 GET + 列表刷新核对实际状态，不把网络超时当作操作必定失败；不会自动发起第二个业务写请求。
- 创建任务每个目标使用独立 Idempotency-Key。接口成功且响应验证通过后清除；网络异常保留用于手动重试。未确认成功的随机键写入当前浏览器标签页 sessionStorage，页面刷新后复用；若浏览器禁用了 sessionStorage，则回退至页面内内存缓存。键不是认证/凭据，不传入日志。
- 原有后端数据库锁、唯一键约束和任务状态/环境校验仍作为最终安全边界。前端锁只是交互层防重，不能代替后端。

## 后端实现

ExecutionTaskService.java：
- createCycleTask、createCaseTask 使用 SELECT ... FOR UPDATE 锁轮次行；存在轮次时**优先查询相同 Idempotency-Key 的旧任务**，验证任务类型及 cycleCaseId 与请求一致后返回旧任务。这样即使首次创建后轮次已 COMPLETED/ABORTED，重试同一键仍然得到原任务。
- 只有不存在旧幂等记录的**全新请求**才继续核验轮次必须 RUNNING、已存在活动任务、用例关联及环境约束；不会凭旧 Key 绕过新任务限制。
- TestCycleService.start 新增 mapper.updateStatus 影响行数必须恰好为 1；无行更新即抛出 409 使事务失败，避免错误报告“开始成功”。abort 原有同类检查保持。
- 无新增表、字段、DDL；无新增任务自动重试。

Java 新增 6 个单元测试：
- 轮次已 COMPLETED，同 Key 的整轮任务返回原任务，不重新 INSERT；
- 轮次已 ABORTED，同 Key 的单例任务返回原任务，不重新 INSERT；
- Key 已用于不同用例，返回 409；
- 新 Key 仍不能绕过已完成轮次；
- 开始轮次状态更新 0 行返回 409，不读取成功详情；
- 没有用例的轮次不能开始，不执行 UPDATE。
