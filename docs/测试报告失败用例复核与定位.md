# 测试报告失败用例复核与定位

2026-11-11 第二十批。仅完善现有测试报告、用例与执行任务。不涉及 Docker、Python/Java Runner、登录或权限。

## 使用方法

打开 http://127.0.0.1:18090/#/test-reports ，在测试轮次操作列点击「结果复核」。弹窗默认只显示失败、阻塞用例，也可以切换到「未执行」或「全部用例」。逐行查看用例编号/名称、结果、执行状态、尝试次数及最近一次执行摘要。

有任务记录的用例可以点击「查看执行」，转至执行任务页，并自动限定轮次、打开准确的单用例任务详情。没有任务记录的用例禁用该按钮。

这是只读复核：不会新建、领取、取消、重试或恢复任何执行任务。

## API

GET /api/test-cycles/{id}/report/review

返回字段严格白名单：cycleId、cycleName、cycleStatus、total、counts，rows 仅含 cycleCaseId、caseNo、title、executionMode、executionStatus、latestResult、attemptCount、taskId、executionId、runnerType、attemptStatus。

- 不返回脚本正文、原始执行 Map、请求快照、环境配置、事件正文、检查点或日志。
- 用例标题/编号经过敏感赋值脱敏。
- 多次执行尝试累计计算；最近执行按最大的 execution ID 确定。
- 尚未产生任务的用例也返回，taskId=null、attemptCount=0。
- Cache-Control: no-store；X-Content-Type-Options: nosniff，防止缓存旧结果。

## 安全定位

前端 util/reportReview.js 限制 ID 为严格正整数。跳转到执行任务页面后重新 GET 任务详情，检查任务 ID、轮次 ID、用例 ID 都一致且任务类型为 EXECUTE_CASE。任意不匹配均拒绝自动打开，不能仅相信 URL 上的标识。
