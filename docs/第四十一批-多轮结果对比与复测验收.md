日期：2026-11-12；T14s 本地目录：D:\code\dev-process-manager

## 需求背景与问题

第40批的真实业务闭环已能走通项目→版本→需求→设计→用例→轮次→执行→报告。原有“测试报告”只能单轮查看通过/失败/阻塞，若一个版本依次完成本地、自测、test3多轮测试，无法方便回答：

- 上轮失败/阻塞的用例，本轮是否变为通过？
- 上轮通过的用例，本轮是否出现回归失败？
- 哪些一直失败/阻塞，哪些只是第一次通过？
- 本轮增加了哪些用例、哪些用例从测试范围移出？

本批补的是**真实业务可读的复测对比**，没有创建新模块、自动执行任务或变更真实历史。

## 业务口径

- **对比对象**：当前轮次所属版本中，按 cycleNo 向前寻找最近一个 **COMPLETED 已完成**轮次。必须同一 versionId 且 cycleNo 更小；不把 PLANNED、RUNNING、ABORTED 或历史状态异常轮次当作已完成基准。
- **同一用例**：按不可变的 testCaseId 关联，绝不按用例编号/标题模糊匹配。改名不会变成新用例；不同 ID 即使名称一致也不能视作同一用例。
- **FIXED 失败转通过**：上一轮 FAIL/BLOCKED，本轮 PASS。
- **REGRESSION 新增回归失败**：上一轮 PASS，本轮 FAIL/BLOCKED。
- **STILL_FAIL 持续失败/阻塞**：上一轮及本轮均在 FAIL/BLOCKED 集合中。
- **STILL_PASS 持续通过**：PASS→PASS。
- **FIRST_PASS 首次通过**：上轮 NOT_RUN/SKIPPED，本轮 PASS。
- **CHANGED 其他状态变化**：其余状态转换（例如 PASS→NOT_RUN），不能擅称修复。
- **NEW_CASE/REMOVED_CASE 范围变化**：仅出现在某一轮的原始用例 ID，不计入已修复/新增回归失败。
- 当前轮次尚未结束时允许查看临时对比，但显示警示“结果可能继续变化”；首次轮次没有之前的已完成参照时明确显示“暂无上一已完成轮次”。
- 这是**结果变化**而非证明缺陷根因被修复；用例修订、环境变化时需结合报告与实际证据分析。
