# 第二十三批：执行任务状态同步及父子任务一致性验收

日期：2026-11-12。项目：dev-process-manager。
范围：只加固既有执行任务与结果汇总，不开发 Docker/Python/Java Runner 或登录权限，不提交或推送 Git。

## 本次发现并修复的缺陷

此前 ExecutionTaskService 和 RunnerService 的部分状态更新逻辑使用 mapper.updateCycleCase(cycleCaseId, status, result) 但未校验返回的影响行数。

可能产生的结果：任务表和 dpm_test_execution 已标记完成、取消或待恢复，dpm_cycle_case 因关联缺失等异常实际未更新；代码仍继续触发轮次自动完成判断与父任务聚合，导致数据之间不一致。

### 新保护

- ExecutionTaskService 新增 requireCycleCaseUpdate(cycleCaseId, status, result)，用于开始执行、等待人工、完成、人工确认/拒绝、取消、恢复与超时待恢复状态。
- RunnerService 新增相同的返回行数校验，完成、Runner 引擎失败与人工介入事件必须同步成功；原 Runner 认领时的更新检查保持不变。
- 更新要求受影响行数恰好为 1，否则抛出 409 业务冲突。上述调用处于 Spring 声明式事务中；抛出运行时业务异常会回滚任务和尝试的状态变更。
- 原有的创建新任务专用 resetCycleCaseForNewExecution 仍负责将最新结果重置为 NOT_RUN，不更改历史执行尝试。
- Runner 支持类型提示同步修正为 HTTP、NODE、BROWSER，实际支持逻辑原本已包含三者。
- 不增加新表，不改任何生产数据，不触碰历史 22 个异常轮次。

## 新增自动化保护

1. ExecutionTaskServiceTest 新增 3 项反向用例：
   - 人工执行完成后，如果轮次用例状态更新影响 0 行，立即拒绝轮次自动完成及追加事件。
   - 超时恢复时任务/尝试已改变，但用例更新失败，拒绝提交事件并触发事务异常。
   - 轮次终止取消任务时，用例状态未同步，拒绝整个操作。
2. RunnerServiceTest 新增 2 项反向用例：
   - Runner 正常完成时用例更新失败，拒绝自动结束轮次。
   - Runner 引擎失败时用例更新失败，同样拒绝继续完成轮次。
3. scripts/audit-task-hierarchy.mjs 新增只读检查：
   - 固定读取本机 127.0.0.1:18090 的 GET API；不发送任何写请求。
   - 检查根任务类型、子任务数量与唯一用例标识；按状态优先级重新聚合整轮父任务。
   - 校验每个用例任务最新 execution 与 task 状态一致、任务关联正确、终态具备合法结果。
   - 对显式 CANCELLED 的父任务按取消语义处理，要求所有子任务均已终态，不用普通子任务优先级误判。
   - 最多检查 500 个根任务，分批 5 个并发；只输出计数与不一致任务 ID，不输出脚本、日志或环境凭据。
4. 已接入 scripts/test-browser-integration.ps1，完整回归附加 -BrowserIntegration 会运行此检查。

## 当前规则与后续
