# 测试环境模块开发记录

## 1. 模块范围

管理测试轮次可选用的环境配置，包括本地、test3、预发、生产等环境。
环境配置是可维护数据，不将环境 URL、认证方式或环境编码硬编码在业务代码中。

本模块已完成环境列表、详情、新增和编辑；不负责登录凭据本身的存储和获取，也不执行测试请求。

## 2. 数据库设计

复用 V1.0.0 已创建的 dpm_environment，不新增 DDL。

| 字段 | 说明 |
|---|---|
| environment_code | 环境编码，全局唯一 |
| environment_name | 环境名称 |
| environment_type | LOCAL、TEST、STAGING、PROD、OTHER |
| base_url | 页面/站点基础地址 |
| api_base_url | API 基础地址，可留空表示沿用 base_url |
| auth_type | NONE、BEARER、BASIC、COOKIE、API_KEY、CUSTOM |
| credential_ref | 本机凭据配置引用，不是凭据内容 |
| config_json | 非敏感配置 JSON 对象 |
| is_active | 是否启用 |
| sort_order | 列表排序 |

当前预置环境为 LOCAL、TEST3、PRE、PROD 四条记录。

## 3. 后端接口

统一前缀：/api/environments

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/environments | 环境列表；activeOnly=true 时只返回启用环境 |
| GET | /api/environments/{id} | 环境详情 |
| POST | /api/environments | 新增环境 |
| PUT | /api/environments/{id} | 更新环境配置 |

## 4. 数据校验与安全

1. environment_code 必须以大写字母开头，只允许大写字母、数字和下划线，长度 2~32，且全局唯一。
2. 环境类型和认证类型必须属于后端允许的枚举值。
3. base_url、api_base_url 只允许 HTTP/HTTPS 地址；URL 不允许携带 userinfo（用户名或密码）。
4. auth_type=NONE 时不允许填写 credential_ref；其他认证方式必须填写 credential_ref。
5. credential_ref 只保存本机凭据配置的引用标识，不在数据库中保存密码、Token、Cookie 或密钥。
6. config_json 必须是 JSON 对象；服务端递归检查对象键名，拦截 password、token、secret、cookie、authorization、apikey、credential、privatekey、clientsecret 等敏感字段名。
7. config_json 的值也不得放入秘密信息；敏感凭据必须由 credential_ref 指向外部本机私有配置。
8. 已停用环境不能用于新建或修改测试轮次；环境当前没有物理删除接口。

## 5. 前端页面

路由：/#/environments

功能：
- 展示环境名称、编码、类型、URL、认证方式、凭据引用和启停状态。
- 可选择是否显示停用环境。
- 新增/编辑环境。
- 配置非敏感 JSON 参数并在前端检查 JSON 格式。
- 页面明确提示禁止保存密码、Token、Cookie、Authorization 和密钥。

## 6. 与测试轮次的关系

创建或修改 PLANNED 测试轮次时，后端读取所选环境并将以下信息写入 dpm_test_cycle.environment_snapshot：

- 环境 ID、编码、名称、类型。
- baseUrl、apiBaseUrl。
- authType、credentialRef。
- configJson（非敏感配置）。

轮次开始后不允许再修改环境配置。环境后续发生变化，不会改写已经保存的轮次快照。
历史轮次的 environment_snapshot 可能为 NULL；列表在快照为空时回退显示当前关联环境名称。

## 7. 验证记录（2026-11-09）

- 数据库 schema_version 为 1.2.0，dpm_environment 已有 LOCAL、TEST3、PRE、PROD 四条初始化记录。
- GET /api/environments/1 可读取环境详情。
- 新增临时环境 DPM_VERIFY（id=5），配置非敏感 JSON：timeoutMs=15000、retryCount=1。
- 使用该环境创建测试轮次 id=3，轮次 environment_snapshot 固定保存上述参数。
- 随后将 DPM_VERIFY 当前配置更新为 timeoutMs=30000；重新读取轮次 id=3，快照仍为 timeoutMs=15000、retryCount=1，验证快照不会随环境更新而变化。
- DPM_VERIFY 为本地联调数据，不是正式环境；当前保留以供查看轮次快照。
