# 本地服务守护与自动恢复

> 实施日期：2026-11-11
> 本地路径：`D:\code\dev-process-manager`
> 运行环境：T14s / Windows 11 / 当前 Windows 登录用户
> **适用范围：本地开发管理系统，不是生产环境高可用方案**

## 目标与结果

已在 Windows 任务计划程序中安装 `DPM-DevProcessManager-Watchdog`，当前用户登录时运行，并在登录后的计划触发周期中每分钟检查一次。

监控四个进程：Spring Boot（18090）、HTTP Runner、Node Runner、Browser Runner。

- **意外退出**：进程确实不存在、无维护暂停且满足依赖条件时，尝试启动；后端使用已编译的 JAR，避免一分钟一轮 Maven 重构建。
- **手动停止**：`stop*.ps1` 会在 `.local` 写独立暂停标记；守护程序不会自动拉起。显式成功运行 `start*.ps1` 才恢复该服务的自动守护。
- **重复进程**：匹配完整 JAR/Runner 脚本路径；有多个实例时只提示，不擅自终止。
- **端口异常**：后端端口被不明进程占用，或者 Java 还在但 `/api/health` 不健康时，不直接强杀进程。
- **PID 文件失效**：存在唯一且路径匹配的真实进程时，修复 PID 文件而不是再启动一个。
- **重启限流**：每个服务 1 小时最多尝试 3 次，超过后需要人工排查。
- **串行执行**：使用 Windows 本地互斥体避免多个守护检查同时运行，计划任务也配置为忽略重叠执行。

**重要：这里只恢复操作系统进程，不会重新执行中断的业务测试用例。** 失联的任务仍按原有租约超时流程进入 `RECOVERY_REQUIRED`，由使用者核对影响后人工确认。

## 常用命令

在 PowerShell 中进入：

```powershell
cd D:\code\dev-process-manager
```

查看状态（不会修改进程）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\service-status.ps1
```

只检查守护策略、不执行重启：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\service-watchdog.ps1 -DryRun
```

对缺失且符合安全条件的进程执行一次修复：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\service-watchdog.ps1 -Repair
```

维护期间暂停整个守护（保留当前进程，不会停止服务）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\watchdog-maintenance.ps1 -Action pause
```

维护结束后恢复：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\watchdog-maintenance.ps1 -Action resume
```

单独手动停止 Browser Runner：`scripts\stop-browser-runner.ps1`；此后守护不会拉起；再次运行 `scripts\start-browser-runner.ps1` 即解除对应暂停。

## Windows 计划任务的安装与卸载

安装程序：`scripts\install-service-watchdog.ps1`。已在 T14s 上实际执行并验证。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-service-watchdog.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-service-watchdog.ps1
```

已经安装时不会默认覆盖；明确要求替换现有同名任务可附加 `-Force`。建议先通过状态脚本检查。

卸载（**仅删除计划任务，不停止运行中的后端/Runner**）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall-service-watchdog.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall-service-watchdog.ps1
```

计划任务采用当前用户的 **Interactive 登录令牌**，不保存 Windows 密码或 Runner Token；不申请管理员权限、不设置唤醒睡眠。触发器为登录时及每分钟一次的重复检查。**未登录 Windows 时不会作为系统服务运行**，电脑休眠或关机时也不会工作。

计划任务运行命令通过 `-NoProfile -NonInteractive -ExecutionPolicy Bypass` 启动本地 PowerShell，只执行仓库下受控的 `service-watchdog.ps1 -Repair`。

## 日志与验证

- 守护事件：`logs/service-watchdog.log`。
- 每服务的重启次数记录：`logs/watchdog-<service>-attempts.txt`。
- 应用与 Runner 输出：`logs/application.*.log`、`logs/http-runner.*.log`、`logs/node-runner.*.log`、`logs/browser-runner.*.log`。
- 暂停标记：`.local/watchdog.paused`；每服务 `.local/watchdog-<service>.paused`。这些都在 Git 忽略目录内。

`scripts/test-service-watchdog.ps1` 默认仅只读检查；**只有明确传入 `-IncludeCrashSimulation`** 才会在确认无运行中任务后，临时停止并重启 Browser Runner 以验证手动暂停、意外退出和 PID 文件修复。

2026-11-11 实测：
- PowerShell 脚本均能解析。
- Browser Runner 手动停止 → `MANUALLY_STOPPED` → 未被拉起：通过。
- Browser Runner 崩溃模拟 → 新 PID 自动启动：通过。
- 将 PID 写为不存在的值 → 自动认领现有唯一进程而不重复启动：通过。
- Task Scheduler 已安装：`DPM-DevProcessManager-Watchdog`，状态 `Ready`。
- 主动运行任务后的 `LastTaskResult=0`：通过。
- 卸载再安装任务且四个进程 PID 均未变化：通过。
- 全局暂停期间运行计划任务 → 记录 `PAUSED`，最后恢复暂停状态：通过。

## 尚未覆盖的边界

本地守护只判断进程存在和 Java 健康检查，并不会自动杀死仍存活但卡住的 Java/Node；Runner 进程“在线但不再领取任务”的深度自愈、电脑关机时运行、系统用户无需登录的后台服务、进程资源隔离和生产高可用均未实现。这些情况需要后续专项设计与验收。
