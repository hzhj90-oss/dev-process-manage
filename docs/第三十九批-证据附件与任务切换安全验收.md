# 第三十九批：证据附件上传、下载完整性与任务切换安全验收

日期：2026-11-12；T14s 路径 D:\code\dev-process-manager；承接第38批开发断点。

## 目标与定位

已有执行任务详情允许上传证据，但上传使用独立的 saving 布尔值（未加入统一任务操作锁），按钮可连续点击/多个上传同时执行；用户切换父任务、子任务或多个 attempt 时，旧文件选择/响应可能落到错误任务；上传 HTTP 超时无法判定服务端是否已保存，盲目重复上传会产生重复附件。后端保存了 SHA-256 和文件大小，下载时原来只查磁盘存在、路径边界，不验证文件实际内容与元数据是否被修改。

本批在不改变数据库表结构、不自动执行真实任务的前提下完成附件的防重、防串数据、只读核对和完整性校验。

## 前端实现

- frontend/src/utils/attachmentSafety.js 提供文件类型/大小合法性检查（10种扩展名、20MB硬限制）、严格限定任务/执行尝试关系、服务端原附件ID与新附件元数据按 SHA-256/大小/类型核对，以及安全的浏览器 SHA-256 计算。
- ExecutionTaskListView.vue 上传前校验显示详情中对应的 taskId/executionId，不允许把整轮父任务ID用作子用例执行附件的 taskId；文件选择成功之后、计算摘要或GET之前，同步加入已有 taskAction 互斥锁，与开始执行/登记结果/人工确认/恢复/取消互斥。
- 原生文件选择框设置 filePickerPending，阻止重复弹框；选择取消会释放。文件上传中禁用全部相关危险操作、关闭详情按钮/遮罩关闭，显示当前按钮 loading。
- 先从服务端 GET 被操作的子任务/独立任务，校验执行尝试属于该任务；保存原附件 ID 快照，成功的 POST 响应必须回传同一 executionId、文件长度、SHA-256、附件类型及有效附件 ID。
- 上传请求发生后如果服务端返回错误或响应未收到，不自动重发 POST，而是读取该 task 下该 attempt 附件列表；只有发现**唯一新ID且 SHA-256/长度/类型完全相符**，才确认服务器确实保存成功。无法确认时显示持续警告，提示用户查看列表后手动决定是否重传，防止重复附件。
- 上传完成始终刷新当前父任务/单例详情；确认成功才给成功反馈；前端不保存原始文件内容、不输出 SHA 输入到日志。
- 证据下载按钮按 taskId/executionId/attachmentId 三元组独立上锁；异步下载完成前会再次确认当前详情仍显示对应 attempt，避免切换任务后误触发旧下载。对返回 Blob 长度与元数据大小做检查，拒绝明显不匹配的文件。
- uploadNotice 错误在详情弹窗内持久显示并提供只读刷新入口，关闭详情后清除；上传期间禁止切换到另一个任务详情。

## 后端完整性

- ExecutionAttachmentService.download 在原有附件归属校验、路径遍历/软链接禁止和 MIME 白名单的基础上，新增实际磁盘长度与记录 fileSize 一致检查；如果保存记录有 SHA-256，计算实际文件摘要并使用 MessageDigest.isEqual 验证，校验失败返回服务端错误而不提供损坏证据。旧历史记录没有摘要时保留兼容的长度检查。
- 不新增 DDL，不改变上传接口签名与原上传事务/文件失败清理机制。
- ExecutionAttachmentServiceTest 新增三项测试：有摘要且文件未损坏应可下载；相同字节长度但内容被篡改必须拒绝；旧记录没有摘要但文件长度不符必须拒绝。
