## 一、为什么做这一批

第46批已完成本机真实浏览器14步操作和业务全量回归，但交付前存在两个容易被忽略的风险。

1. Git有大量未提交内容。普通 git status --short 按目录汇总未跟踪文件，不能体现每个文件；git diff --check 只检查已跟踪的修改，不能证明新增源码是安全、完整且能够同步的。
2. 现有发布预检只要求找到一份可校验的JAR快照，未强制确认**当前正在运行的JAR也有匹配快照**。同时部分嵌套PowerShell调用没有显式隐藏窗口参数。

本批不追求增加新业务菜单，而是补交付审计、安全门槛和可重复验收。
