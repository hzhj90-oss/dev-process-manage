# 第二十六批：核心列表乱序响应、加载错误与项目编辑目标固定

日期：2026-11-12。项目目录：D:\code\dev-process-manager。

## 问题和修复

1. **快速筛选/分页时旧请求覆盖新结果**：原始页面会无条件应用每个请求返回的 list/total，并无条件清除 loading。如果请求 A 先发后到、请求 B 后发先到，A 可能覆盖 B 的最新选项，或者旧请求的 finally 提前取消 B 的加载中提示。
   - 新增 frontend/src/utils/latestRequest.js。每次请求分配递增版本号，只有最新版本的成功、失败与 finally 能修改页面状态。
   - 项目、版本、需求、测试用例、测试轮次五个核心列表统一应用此保护。
2. **最新请求失败时只弹一次提示，旧结果仍留在表格里**：现在对当前请求出错会清空旧列表、总数归零，在列表上方显示持续可见的失败原因，并提供「重试加载」按钮。旧请求失败则直接忽略，不误清空新数据。
3. **编辑项目时在当前分页列表中再次查询 ID**：原来的保存逻辑使用 rows.find(projectCode)，若编辑表单打开后页面刷新或筛选导致该行不在列表内，会丢失编辑目标并报错。
   - 打开编辑时固定 editingId；创建时重置 editingId；保存调用 projectApi.update(editingId, payload) 而不是重新搜索当前列表。
   - 所有改动仅限前端，不修改 API、数据库结构或原有数据。
