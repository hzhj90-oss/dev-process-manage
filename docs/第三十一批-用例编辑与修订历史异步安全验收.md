# 第三十一批：测试用例编辑与修订历史异步安全验收

日期：2026-11-12。项目：`D:\code\dev-process-manager`。

## 问题定位

旧 `TestCaseListView.openEdit(row)` 会先等待需求/脚本下拉接口，再查询详情。用户若在网络慢时关闭 A 并打开 B，A 的详情可能迟到而写进 B 的表单；加载异常时只显示瞬时消息、关闭弹窗，无法直接重试。修订历史读取和点击不同版本的异步响应也没有防止旧请求覆盖当前详情的保护。此类问题不一定每天可复现，但可能把编辑目标与展示字段错配，所以属于正常使用稳定性问题。

## 本批修复

- `frontend/src/views/TestCaseListView.vue` 的编辑弹窗增添 `editorGate`、`editorToken`、`editorLoading` 与 `editorError`。点击编辑时立即清空上一个用例的表单，并行读取当前详情及需求/脚本选项；仅当前弹窗的最新详情 ID 匹配、响应修订及需求格式合法时才能赋值。
- 关闭弹窗、组件卸载后让编辑详情、关联需求和脚本选项的旧请求失效。显示加载状态；失败保留弹窗与可见错误，支持「重试读取用例详情」；详情未完成/失败时禁用表单和保存操作。
- 保存前、异步表单验证后均检查当前编辑会话及所需选项完成状态。保存请求进行中禁用取消和关闭，防止切换编辑对象后混淆成功提示；仅当前有效会话才关闭弹窗和刷新列表。
- 修订历史增添 `historyGate` 与 `revisionGate`：关闭/切换用例/选择不同修订时，旧响应不覆盖新版本；失败可从当前用例「重试加载历史」。修订详情响应也核对对应 revision ID。组件卸载时失效所有请求。
- 只改前端和测试：不改后端 API、数据库 DDL、测试结果、执行器或历史轮次。

## 真实 Chrome 异步回归

新增 `runner/browser-runner/browser-case-editor-race-smoke.mjs`，纳入 `scripts/test-browser-integration.ps1`。无头 Playwright 在浏览器拦截 GET，故意使旧请求迟到：

1. 打开用例 A，延迟其详情及需求下拉；在加载中确认保存被禁止，关闭 A，再打开 B。
2. B 首次 GET 503，确认显示持续错误且保存被禁止；点击「重试读取用例详情」，确认 B 正确显示。
3. 释放 A 的旧详情和需求响应，确认 B 表单与当前需求列表不被覆盖。
4. 打开 A 修订历史，在列表加载中关闭；打开 B 修订历史，在 B 的两个修订版本快速切换，同时让 A 历史以及 B 的旧修订详情迟到。只允许当前 B 修订留在页面。
5. 全程不发送 POST/PUT/DELETE 到真实服务、不创建业务记录。
