# 第二十二批：历史轮次状态只读诊断与验收

> 2026-11-11。开发管理系统。用户明确要求 Docker/Python/Java Runner 和登录权限暂不开发；继续完善现有测试功能，未获授权不做 Git commit/push。

## 功能入口

打开 http://127.0.0.1:18090/#/test-cycles ，点击页面右上方的 **轮次状态诊断**。

诊断弹窗只列出满足以下条件的轮次：
- 轮次状态依然为 RUNNING（进行中）；
- 该轮至少有 1 条测试用例；
- 该轮全部用例都处于 COMPLETED 或 CANCELLED 终态。

结果展示轮次编号、名称、所属项目/版本、用例总数及终态构成、根执行任务总数和活动任务数。依据根任务记录分为三类：仍有活动根任务、无活动根任务、无根任务记录。支持单击「查看轮次」打开已有的轮次详情。

**本功能不提供自动完成、批量修正、任务取消或重新执行操作**。即使诊断认为全部用例已完成，也不应跳过业务核查而直接修改历史轮次。

## 只读 API

GET /api/test-cycles/diagnostics?limit=100

- limit 默认 100，范围 1～200，越界返回 HTTP 400；查询多取一条用于判断是否截断。
- 响应只包含必要的元数据，readOnly=true、limit、count、truncated、activeRootCycles、noActiveRootCycles、noRootTaskCycles、items。
- 每条记录只包含 cycleId、cycleNo、cycleName、cycleStatus、projectName、versionNo、createdAt、用例/根任务数量和 diagnosticCategory。
- 不返回脚本源码、环境配置、token、请求快照、事件正文、检查点或日志。
- HTTP 响应带 Cache-Control: no-store、X-Content-Type-Options: nosniff。
- 数据库查询使用独立聚合的用例与根任务派生表，MySQL 5.7 兼容，无 DDL，无数据库写入。

## 真实数据分类结果

第二十二批在本机 dev-process-manager 数据库执行：

- 45 个轮次的跨模块一致性巡检：73 条用例、78 次执行尝试，结果计数硬错误 0，历史状态告警 22。
- 新的状态诊断 API 对同一数据库返回候选轮次 22，activeRootCycles=0，noActiveRootCycles=22，noRootTaskCycles=0，truncated=false。
- 即：22 条候选轮次全部没有活动中的根执行任务，同时其全部用例已处于终态。它们看起来属于较早的端到端回归/开发测试记录，但**不能仅凭状态推断数据应被自动修复**。
- 没有对 22 条历史轮次执行 UPDATE、POST、DELETE，也没有对现有业务任务进行自动取消或恢复。
