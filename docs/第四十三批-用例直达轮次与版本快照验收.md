# 第四十三批：测试用例直达计划轮次及跨版本覆盖保护

日期：2026-11-12；位置：D:\code\dev-process-manager

## 起因与真实业务问题

第42批完成“需求→一键创建关联用例”，但保存后用户还需切换到测试轮次、寻找目标版本/环境/计划轮次、打开详情并在巨大用例下拉列表中再次搜索。缺少“从当前测试用例直接加入目标轮次”的精确操作。

进一步核对后端 TestCycleService.captureCases：通用用例允许任意版本使用，而已关联需求的用例实际快照只获取**当前轮次所属版本**的关联需求和详细设计。因此如果把已有需求关联的用例随意添加到另一个版本，可能出现“用例快照已加入、需求覆盖快照却为空”的误解。不能简单添加一个忽略版本边界的快捷按钮。

## 本批主要实现

### 用例列表的一键加入入口

- TestCaseListView.vue 用例行新增“加入轮次”，仅 ACTIVE 用例可用；点击使用只读深链 test-cycles?caseId=原始用例ID。URL使用严格正整数单值，不信任 query 中任何版本名称或需求信息。
- 该入口适用于刚创建的用例、已有的回归用例和经需求列表下钻找到的用例，不需要手工跨模块复制编号。

### 测试轮次页面的关联向导

- 轮次页当合法 caseId 来源存在时展示上下文提示及“选择目标轮次”入口。不会因为打开 URL 自动写数据库或创建任务。
- 点击后 GET 真实用例详情、完整分页加载所有状态为 PLANNED 的轮次；用例必须 ACTIVE、有当前有效修订，且所属需求需带 versionId。任何详情/分页数据格式不全时拒绝提供不完整候选。
- 关联了一个或多个需求的用例只展示**与这些需求所属版本一致**的计划中轮次；如果用例跨多个版本关联，则能看到这些版本各自的计划中轮次。跨版本但未关联该版本的轮次不展示，避免产生虚假的需求覆盖认知。
- 没关联需求的通用用例可加入任意版本的计划轮次，但明显提示“**不自动产生需求覆盖快照**”，由用户有意识决定。RUNNING、COMPLETED、ABORTED 的轮次不作为可选候选。
- 若没有符合条件的计划中轮次，可直接在向导中选择目标版本，点“新建轮次并预选用例”，转到原新建轮次表单并带入 versionId 与该用例 ID；仍然要人工填写环境、代码版本等必填字段并确认保存。新建不是自动写入。

### 加入轮次的双重验证与错误恢复

- 用户点击“加入所选轮次”后立即取得 placementBusy/cycleMutation 排他锁；在确认对话框、二次 GET、POST 和读取结果期间，原弹窗不能关闭或连续触发，防双击。
- 确认文案明确目标轮次名称、环境和需求快照规则。确认后同时重新 GET 来源用例和目标轮次，检查用例仍 ACTIVE、修订ID和关联版本集合未变，目标 ID 和版本确实匹配、状态仍 PLANNED、此前未包含该用例。所有检查通过才调用原有 POST /api/test-cycles/{id}/cases。
- POST 成功必须在响应轮次的 cases 中看见当前原始用例 ID；若网络丢失响应或失败，不自动重发 POST，只读 GET 目标轮次确认是否已经保存。确认有新用例时按完成处理，不能确认时显示持久错误并要求人工复核。
- 成功后返回按所属版本过滤的轮次页、打开刚加入的目标轮次详情，可查看被冻结的修订和需求/详细设计快照；不自动开始测试，不创建执行任务。

### 后端响应的版本归属

- TestCaseRequirementDTO.java 新增只读 versionId 字段；MyBatis TestCaseMapper.xml 中 selectRequirementsByCase 的 SELECT 增加 r.version_id AS version_id。用于正确区分同一个需求编号在多个项目或版本中的版本归属。
- 本批只增强 GET 返回，不更改数据库字段、关系表、已有保存事务或历史数据；原有快照规则保持不变。
