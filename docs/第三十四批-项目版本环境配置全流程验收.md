## 发现的问题

1. 项目、版本、环境三个表单的“保存”原本在异步 `formRef.validate()` 之后才设置 `saving=true`，用户快速双击可能并发发送多次 POST/PUT，产生重复创建/多次更新。校验和请求进行期间也允许关闭弹窗，异步保存结果可能归属到随后打开的表单。
2. 版本页面的项目选项只读取 `ACTIVE`；对已有版本，如果所属项目已经停用，编辑下拉框无法显示原项目标签，容易误以为关联失效。项目选项失败时也未阻止保存。
3. 环境页面 `loadData()` 无请求版本保护，连续切换“显示已停用环境”时早发晚到的响应可以覆盖最新过滤；加载失败后只弹一次消息，旧表格仍残留，且无持续可见重试入口。
4. 环境 JSON 配置已有前端基本格式检查，本次进一步纳入保存锁定和真实 Chrome 验证，保证无效 JSON 不会发出业务请求；`NONE` 认证模式保存时必须清除旧凭据引用。

## 代码变更

### 项目管理 `ProjectListView.vue`

- 保存会话引入 `editorGate`、`editorToken`；打开新建/编辑时建立会话，关闭及卸载时失效。
- 用户点击保存后立即设置 `saving=true`，将异步校验也纳入临界区；保存前核对当前表单、会话和固定编辑 ID。重复点击、切换编辑对象和保存中的关闭都受到保护。
- 请求成功后仅当前会话更新 UI 和刷新列表；失败保留原表单，允许修改和再次保存，不生成重复请求。
- 列表原有 latest-only 保护与项目到版本导航保持不变。

### 版本管理 `VersionListView.vue`

- 新增 `projectsGate/projectsLoading`，多次重试项目选项时仅最新请求生效；出错或加载中不能盲目新建/保存。
- 既有版本所关联的项目若已停用，编辑时保留原关联项目的标签作为只读来源的选项，同时允许从活跃项目中选择新的归属。不会在新建版本时额外提供停用项目。
- 表单改用与项目一致的同步保存锁、固定版本 ID、校验后再核对会话，保存期间禁用关闭及取消；保留已有起止日期校验与提交字段。
- 版本列表原有 latest-only 分页加载、跳转需求/测试轮次行为保持不变。

### 测试环境 `EnvironmentListView.vue`

- 增加 `listGate/listError`：按最新 GET 更新列表和加载状态；旧请求成功/失败不覆盖新结果；当前请求失败清空旧表格，显示持续错误及“重试加载环境”按钮。
- 新增环境编辑会话 `editorGate/editorToken`，锁定目标 ID，异步校验与请求期间禁止重复保存及关闭。异常保存保留表单；成功后刷新当前列表。
- 环境安全边界不变：非敏感 JSON 必须是合法对象，认证 `NONE` 必须将 `credentialRef` 清空，服务器仍是最终校验入口。
