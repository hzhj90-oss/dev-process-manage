# 第三十三批：详细设计弹窗与脚本库列表异步安全及重试

日期：2026-11-12。工程目录：`D:\code\dev-process-manager`。

## 发现的实际缺陷

- `RequirementListView.openDesigns(row)` 原来只把列表从接口直接赋给 `designs`，没有对弹窗关闭、A→B 切换和重试做请求隔离。如果需求 A 的 GET 在关闭后才返回，会把 A 设计显示给需求 B。列表 GET 报错只给出一次性消息，不支持原位重试。新增修订 `saveDesign()` 原来在表单异步校验后直接读取当前 `selectedRequirement.id`，有被切换需求影响的风险。
- `TestScriptListView.loadData()` 原来每次请求均无条件改写 rows/total/loading。旧查询晚到会覆盖新筛选；新请求 503 时仍保留旧脚本列表，用户容易把过期的记录当作当前筛选结果。

## 改进

### 需求详细设计（`frontend/src/views/RequirementListView.vue`）

- 新增 `designGate`、`designToken`、`designLoading` 和 `designError`；每次读取形成单独代号，只在当前需求 ID、弹窗仍打开、该请求仍最新时才能展示结果。关闭或路由卸载失效旧请求。
- 设计列表加载中显示加载效果，避免误显示“暂无设计”；异常显示持续错误与「重试加载详细设计」按钮。列表未完成或失败时禁止新增修订。
- 新增修订时将 `newDesignRequirementId` 固定为原所属需求；表单异步校验后再次核对父级请求会话和需求 ID；保存时只使用该固定 ID，不再实时读取可能变化的选择对象。
- 保存期间禁用取消、关闭及父弹窗的关闭按钮，避免未完成提交时用户继续切换归属；服务返回后只在会话仍正确时插入最新修订、刷新列表。没有改动后端 API 与数据库结构。

### 脚本库列表（`frontend/src/views/TestScriptListView.vue`）

- `listGate` 实现 latest-only；旧搜索、翻页、刷新请求的完成/错误/finally 都不能修改新结果。
- 当前请求失败时清空旧表格和总数，显示持续错误与「重试加载」。成功结果验证 `list` 是数组、`total` 是非负安全整数，避免把异常响应当作空表。
- 卸载页面失效在途列表请求，不影响已经加固的脚本编辑和修订历史。

## 自动化

新增 `runner/browser-runner/browser-design-script-list-race-smoke.mjs`，纳入 `scripts/test-browser-integration.ps1`，用 Playwright **无头 Chrome** 模拟以下场景：

1. 需求 A 设计列表 GET 阻塞，关闭 A；需求 B 第一次 GET 返回503，验证禁止“新增修订”，点击重试后 B 数据正确显示。
2. 释放 A 旧响应，确认 B 的列表及标题不被污染。
3. 在 B 的弹窗新增修订，使用浏览器拦截 POST 检查 URL 必须是 B 的需求 ID、请求正文字段正确，再返回模拟修订；**此 POST 不到达真实服务**。
4. 脚本库查询 OLD 阻塞，快速查询 NEW 成功，释放 OLD 后只显示 NEW。
5. 再模拟新的脚本查询 503：页面必须清空旧列表，显示错误并可重试；恢复后显示新结果。
