# 系统架构与本地运行约束

## 1. 架构目标

系统采用前后端分离的代码组织方式，但本地运行时由同一个 Spring Boot 进程提供前端静态页面和 REST API。用户只需访问一个 HTTP 端口，不单独暴露 Vite、Nginx 或 Gateway 端口。

## 2. 目录职责

```text
D:\code\dev-process-manager
├── frontend/       Vue 3 + Vite + Element Plus
├── backend/        Java 8 + Spring Boot + MyBatis
├── database/       MySQL 版本化迁移脚本
├── docs/           架构、数据库设计和模块开发记录
├── scripts/        构建、启动、停止脚本
├── .local/         本机私有配置（忽略提交）
├── data/           上传文件和执行附件（忽略提交）
└── logs/           应用日志（忽略提交）
```

## 3. 单端口运行

1. 在 frontend 执行 Vite production build。
2. Vite 将静态文件输出到 backend/src/main/resources/static。
3. Maven 将静态资源与 Spring Boot 后端一起打包为 backend/target/dev-process-manager.jar。
4. Spring Boot 启动内嵌 Web Server，统一提供前端页面和 /api/** REST 接口。
5. 浏览器访问 http://127.0.0.1:18090。


## 4. 组件职责

- Vue 3：项目、版本、需求、详细设计、测试用例、脚本库、测试环境和测试轮次页面。
- Spring Boot 2.7.18：REST API、业务校验、事务边界和静态页面服务。
- MyBatis：数据库访问，Mapper XML 负责 SQL，Service 负责业务规则。
- MySQL 5.7.44：保存项目管理数据、修订历史、轮次快照和后续执行记录。
- T14s Desktop Commander Tunnel：供 ChatGPT 在授权范围内操作本机文件、构建工具和 Java 进程。
- 独立 Runner：HTTP Runner 执行只读 HTTP DSL；Node Runner 使用 QuickJS WASM 执行受限 JavaScript 子集。两者均通过本机 API 领取任务并回传事件/结果，不在 Spring Boot 进程内执行用户源码。

## 5. 当前已实现的业务链路

```text
项目
  -> 版本
      -> 需求
          -> 详细设计修订
      -> 测试用例及用例修订
          -> 需求覆盖关系
      -> 测试轮次
          -> 固定测试环境快照
          -> 固定用例修订快照
          -> 固定需求和详细设计快照
          -> 开始 / 终止轮次
          -> 执行任务（整轮父任务 / 单用例子任务）
              -> MANUAL / CHATGPT 执行
              -> SCRIPT + HTTP：独立 HTTP DSL Runner
              -> SCRIPT + NODE：独立 Node Runner（QuickJS WASM）
              -> 事件、断言和结果回传
```

测试轮次除管理计划、环境、代码基线和用例快照外，已支持创建执行任务；MANUAL/CHATGPT 由任务 API 执行，HTTP/NODE 固定脚本由独立 Runner 领取并回传事件和结果。

## 6. 测试执行链路（已实现与后续）

```text
测试轮次
  -> 创建执行任务
  -> ChatGPT 分析用例和执行方式
  -> 选择固定脚本 / 动态生成脚本 / 人工执行
  -> HTTP DSL Runner / Node QuickJS WASM Runner / ChatGPT / 人工执行
  -> 收集断言、日志、请求响应和执行事件
  -> 保存每次执行记录
  -> 后续补充截图、附件和测试报告
```

任务状态描述执行过程；PASS、FAIL、BLOCKED 等描述测试结论。同一用例允许在同一轮次多次执行，attempt_no 保留每次尝试。执行任务 API、HTTP Runner、Node Runner、ChatGPT AI 任务队列发现、原子认领、事件/检查点、人工介入重新入队及显式恢复协议均已实现并通过本地端到端协议验证；ChatGPT 侧由当前对话或 E2E 客户端调用，应用本身不运行自主模型 worker。并发 ChatGPT 开始、检查点持久化、完成与轮次终止竞态、父任务聚合和轮次终止后的迟到请求拒绝已通过 E2E 验证；Runner 租约过期/心跳的数据库时钟与行锁竞态已通过 MySQL 集成测试。Python/Java Runner、浏览器自动化、截图附件和报告仍待完成。

## 8. 本地配置与安全

- 数据库密码放在 .local/application-local.yml，不提交到代码仓库。
- 应用通过该文件配置本地数据库连接；默认数据库为 dev_process_manager。
- 测试环境表只保存 credential_ref，不保存 Token、Cookie 或明文密码。
- HTTP Runner 仅执行只读 HTTP DSL；Node Runner 的用户脚本在 QuickJS WASM 中执行，不暴露宿主 Node.js、文件系统、子进程和网络 API，限制 5 秒、32 MiB guest heap 和 512 KiB 栈。该实现是受限 JavaScript 子集，不是完整 Node.js 运行时。
- config_json 只允许保存非敏感 JSON 配置；服务端递归检查敏感字段名。
- 上传附件规划保存在 data/uploads，数据库保存文件元数据和相对路径。
- 生产环境默认禁止自动化写操作；涉及生产变更必须设置人工确认门槛。
- 当前本地服务默认绑定 127.0.0.1，尚未开放 LAN。
